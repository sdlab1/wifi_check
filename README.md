# wifi-diagnostic

Комплексный bash-скрипт для диагностики Wi-Fi и интернет-соединения в Linux.
DIY: просто скормите вывод скрипта консоли нормальному llm - и он сразу скажет причину (если причина есть) неполадок wifi/internet connection.

Скрипт помогает быстро понять, **где именно теряются пакеты** — в вашем Wi-Fi,
у провайдера, или у оператора мобильной сети — и показывает текущие настройки
драйвера, энергосбережения и стека TCP/IP.

## Возможности

- 🔍 Автоопределение Wi-Fi интерфейса (не привязан к `wlan0`)
- 📡 Информация о драйвере, режиме USB (2.0/3.0), сигнале и скорости
- ⚡ Проверка энергосбережения (NetworkManager, `iwconfig`, `modprobe.d`)
- 🌐 Состояние TCP/IP стека (BBR, буферы, SACK, ECN)
- 📊 Ping нескольких целей с прогрессом в одну строку
- 🗺️ MTR с разбивкой потерь по хопам
- 🎨 Цветной вывод (отключается при перенаправлении в файл)

## Зависимости

```bash
sudo apt install inxi iw iproute2 iputils-ping mtr-tiny
```

Скрипт работает на Debian, Ubuntu, MX Linux, Linux Mint и любом другом
дистрибутиве с пакетом `mtr-tiny`.

## Использование

```bash
chmod +x wifi-check.sh
./wifi-check.sh
```

## Настройка

Отредактируйте переменные в начале скрипта:

| Переменная | Описание | По умолчанию |
|---|---|---|
| `PING_TARGETS` | Массив целей для ping | `1.1.1.1`, `8.8.8.8`, `openrouter.ai`, `opencode.ai` |
| `PING_COUNT` | Пакетов на каждую цель | `100` |
| `PING_INTERVAL` | Интервал между пакетами (сек) | `0.2` |
| `PING_TIMEOUT` | Таймаут ответа (сек) | `2` |
| `MTR_TARGETS` | Массив целей для mtr | `openrouter.ai`, `opencode.ai` |
| `MTR_COUNT` | Probes на хоп | `50` |
| `LOG_FILE` | Путь к лог-файлу (пусто = без лога) | `""` |

## Как читать результаты

### MTR — главный инструмент

```
HOST: TCm710q                  Loss%   Snt   Last   Avg  Best  Wrst StDev
  1.|-- _gateway                0.0%    50    2.1   4.5   2.1   6.2   1.2
  2.|-- 10.126.9.243           12.0%    50  1360. 791.3  22.2 1541. 482.5
  3.|-- 10.250.11.42           12.0%    50  1346. 773.7  18.8 1516. 469.1
```

Читайте так:

- **Хоп 1** — ваш роутер/телефон. Должен быть **0.0%** потерь и RTT <10 мс.
  Если тут потери — проблема в Wi-Fi.
- **Хоп 2** — первый роутер провайдера/оператора. Потери отсюда — **не ваша
  проблема**, это сеть провайдера.
- **Разброс Best vs Avg** — если `Best` <50 мс, а `Avg` >500 мс, это
  **bufferbloat**: канал физически быстрый, но перегружен буферами на стороне
  оператора. Лечится только SQM на стороне оператора, FEC-туннелем
  (UDPspeeder, kcptun) или сменой провайдера.

### Ping — итоговая статистика

```
600 packets transmitted, 534 received, 11% packet loss
rtt min/avg/max/mdev = 15.913/888.694/1775.786/490.645 ms
```

- **packet loss**: 0% — идеально, <1% — приемлемо, >5% — плохо.
- **avg RTT**: <50 мс — отлично, 50–150 мс — норма, >300 мс — плохо.
- **mdev** (стандартное отклонение): <20 мс — стабильно, >100 мс — «джиттер».
- **pipe N** в выводе ping: количество пакетов в очереди. >5 — признак
  bufferbloat.

## Типичные сценарии

### Wi-Fi отличный, интернет плохой

```
Хоп 1: 0% потерь, 4 мс
Хоп 2: 12% потерь, 900 мс
```

Драйвер и адаптер ни при чём. Проблема в сети оператора. Решения:
внешняя антенна, репитер, смена оператора, FEC-туннель.

### Wi-Fi плохой

```
Хоп 1: 5% потерь, 80 мс
Хоп 2+: как хоп 1
```

Проблема в Wi-Fi. Проверьте:
- Уровень сигнала (`signal:` в секции 4). Хуже −70 dBm — плохо.
- `tx retries` и `tx failed` — если растут быстро, эфир грязный.
- Энергосбережение должно быть **выключено** (секция 5).
- Параметры драйвера `disable_usb_sg=1` и `rtw_disable_lps_deep_mode=1`
  (для Realtek RTL8812BU/8822BU).

## Известные проблемы

### Realtek RTL8812BU / RTL8822BU

Встроенный драйвер `rtw88_8822bu` (ядро 6.12+) в целом работает хорошо,
но иногда выдаёт в dmesg:

```
failed to get tx report from firmware
```

Это предупреждение, а не ошибка. Если `tx retries` и `tx failed` в
`station dump` не растут — можно игнорировать.

Полезные параметры драйвера (`/etc/modprobe.d/rtw88_8822bu.conf`):

```
options rtw88_8822bu disable_usb_sg=1 rtw_disable_lps_deep_mode=1
```
